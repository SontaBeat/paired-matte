# 完整流程：从原图到透明 PNG

可先打开[图文分步演示](../walkthrough.html)，用已完成的纱物素材跟做网页导出，再按本文处理自己的图片。

## 1. 准备与主体范围

保留原图。记录宽高和应保留的主体：人物之外的武器、饰品、薄纱、坐骑、法器和特效也需要明确。不要仅写“人物白色”导致其他主体漏掉。

默认底色为 `#808080`，也可约定其他纯色，但生图、记录和网页中的底色必须一致。图像若已有可靠 Alpha，可直接从 Alpha 合成纯色图并导出遮罩，跳过生图。

每张图使用独立工作目录，建议保存：`source.png`、`solid-raw.png`、`alpha-raw.png`、`alpha.png`、`alignment-overlay.png`、`solid.png`、`cutout.png`、`settings.json`、`run-notes.md`。遮罩通过检查前不要覆盖已有成品。

## 2. 网页版生成纯色图

登录用户自己的 ChatGPT 网页版，确认能使用生图。一次处理一张原图，新建一个会话，上传原图并发送 [纯色图提示词](../skills/gpt-image-2-subject-assets/references/prompts.zh-CN.md)。

等待生成完成，下载实际图片文件，不使用聊天截图。检查身份、姿势、裁切、武器端点、主体位置和材质。变化明显则用针对性纠正重试；不要将已经变形的结果传给下一步。

保存为 `solid-raw.png`。即使看起来是纯灰，实际像素也可能有轻微渐变。

## 3. 用纯色图生成遮罩

在同一张图的会话里重新上传刚下载的 `solid-raw.png`，明确它是本步唯一几何参考，发送 [遮罩提示词](../skills/gpt-image-2-subject-assets/references/prompts.zh-CN.md)。上传的文件名和提示词应对应，避免误用原图。

要求背景黑、不透明主体白、真实半透明区域灰。灰色不是衣服阴影；深色头发也不应因为“颜色黑”而在 Alpha 中变黑。

下载为 `alpha-raw.png`。不要一次要求模型输出左右拼在一张图上的“灰底＋遮罩”，那会增加尺寸、裁切和对齐的不确定性。

## 4. 尺寸、Alpha 与轮廓检查

使用 [检查脚本](../skills/gpt-image-2-subject-assets/references/validation.md) 将遮罩转为单通道 `L`，统一到源图画布。少量画布尺寸差异可归一化；裁切、构图改变不是缩放能解决的问题。

**对齐叠加必须用未经遮罩裁边的 `solid-raw.png`。** 若先按错位遮罩切掉彩色图，再检查两者，可能把错误藏起来。

在网页里导入 raw 纯色图和归一化遮罩，选择“红线轮廓”和“原尺寸”；或查看脚本生成的叠加图。检查头顶、四周极值、剑尖、细带、孔洞、脚部。红线只是阈值边界诊断，尤其对光晕不能代替透明度质量检查。

若存在局部变形或位移，只重新生成遮罩。针对同一问题先重试一次；仍失败则记录失败、保留素材，停止将该对标记为完成，和用户商量人工修复或换方案。不要用大幅阈值裁切来掩盖几何错误。

## 5. 纯色归一与透明输出

遮罩通过后，可用辅助脚本把零 Alpha 的背景像素设为精确底色。它不会修正半透明区域内部混入的渐变；因此仍要检查原始纯色图质量。

在网页输入配对图，指定正确底色。默认通用模式保留遮罩的透明度，禁用白纱中和与灰边削弱；“灰底反推”仍是受限混合。白纱模式使用历史经验参数，适合当作调节起点。

按黑、白、棋盘格三种底预览，观察灰边、暗纱、颜色偏移、断裂、边缘锯齿。通过后下载透明 PNG，记录预设和滑杆值。若高要求交付，还应放到实际目标背景上验收。

## 6. 串行批处理与中断恢复

按文件名稳定排序，一张完整完成后再处理下一张；每张新会话，不在一个会话堆积整个批次。这个约定是为了减少参考图混用、便于追踪，不代表能保证避免服务限额或风控。

登录、验证、人机挑战和限额出现时，记录最后完成的阶段并暂停网页调用。由用户正常处理登录或等待额度，之后复用已下载的有效素材。不要换账号、并发会话或快速重试来绕过限制。

`run-notes.md` 记录来源文件名、尺寸、执行方式（web/builtin/source-alpha）、纯色、已完成阶段、实际提示词、重试原因、对齐检查结果与最终参数。不要把 Cookie、会话链接、下载签名链接或私人绝对路径提交到公开仓库。

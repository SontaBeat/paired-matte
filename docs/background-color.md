# 纯色背景的选择

## 默认推荐：#808080

使用中性中灰 **#808080（RGB 128,128,128）**，不要只写“浅灰色”。明确色值有利于生成、记录与本地工具保持一致；#808080 是这里的工程约定，不是线性光空间的 50% 灰。

选择理由：

1. **通道中性**：R、G、B 数值相同，相比彩色底不额外引入单一色相的背景混色方向。这不保证模型不会产生偏色。
2. **兼顾明暗细节**：中灰与白色薄纱、浅色发丝存在亮度差，也不会像纯黑一样让深色细节难以观察。它是检查时的折中背景，并非对所有主体对比度都最大。
3. **明确反推参数**：在合成模型 I = αF + (1−α)B 中，均匀且已知的 B 能减少背景估计的不确定性；模型生成的 Alpha 仍需要检查。
4. **便于重复和批量处理**：所有文件使用同一约定，可复用提示词、网页设置、检查命令与异常判断规则，降低不同批次混用底色的风险。

## 不是色键抠图

本方法不因像素接近 #808080 就将它删掉。配对遮罩决定透明度，彩色图用于估计前景颜色。因此主体可以包含灰色；关键是遮罩是否正确，而不是刻意选择一种主体中绝不存在的颜色。

## 其他颜色何时可用

若已有素材使用其他已知纯色，或中灰难以观察某些局部细节，可以使用不同纯色；但须同步修改生成提示词、脚本的 --background 参数、网页“指定背景颜色”和参数记录。若更换生成底色，应重新准备匹配的彩色图并复查遮罩，不要只改网页参数。

纯黑便于观察浅色发光细节、纯白便于观察深色轮廓，但可能掩盖同色系细节；饱和彩色底可能带来更明显的混色。颜色选择应服务于具体素材的检查，没有经过对照实验的普遍最优色结论。

## 质量要求

- 生成底色必须均匀，无渐变、投影、地面或纹理；半透明区域应透出同一种底色。
- 生成图片看起来是中灰，不代表像素精确等于 #808080。轮廓验收通过后，可将零 Alpha 区域归一为精确底色。
- 归一化不修正半透明区域内已混入的错误背景，也不能修复错位。
- 小 Alpha 会放大底色与遮罩误差；更换颜色不能消除该问题。
- 最终在黑、白、棋盘格与目标背景上检查，不仅检查灰底图。
